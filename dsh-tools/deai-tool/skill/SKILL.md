# deai

给文字和界面做 lint。它是**预检**，不是裁判：报告干净不等于写得好，报告有问题也不等于写得差。

## 什么时候跑

- 写完文章、文案、报告、邮件，交付前
- 改完网页、组件、样式，构建前
- 被要求"去 AI 化"时，作为第一道筛子（人还要通读一遍）

## 怎么跑

工具在 `C:\Knowledge base\02-Project\deai-tool`，Node 24 直接跑 TypeScript，零编译。

```powershell
cd "C:\Knowledge base\02-Project\deai-tool"

# 文本（Markdown / 纯文本）
node src/cli.ts text ..\path\to\file.md --json

# 界面（HTML / CSS / astro / tsx）
node src/cli.ts ui ..\path\to\dir

# 把间距归到 4px 栅格（只动 padding/margin/gap 的 px 值，向上取整）
node src/cli.ts ui ..\path\to\dir --fix
```

参数：`--json` 机器读；`--strict` 启用默认关闭的节奏类规则（TXT-003/004/006、UI-008）；`--rules <file>` 换规则集。

退出码：有 `error` 时为 1，可直接挂 CI。

## 规则在哪

- `rules/text.json` 10 条：模板引导词堆叠、空话词密度、连续段首同构、段长等齐、结尾复述开头、小标题过密、数字无来源、绝对化断言、套话句式、emoji。
- `rules/ui.json` 8 条：紫蓝渐变、渐变文字、玻璃拟态、发光阴影、emoji 当图标、间距不在栅格、假数据、首屏三按钮。

每条都带 `source`（AGENTS§4 / humanizer 章节 / unslop 清单）和 `fix`。

## 怎么读报告

1. **先看 error**：渐变文字、断链这类是硬伤。
2. **再看 warn**：模板词、绝对化断言、假数据。
3. **info 只当提醒**：间距不在栅格、标题过密，可能是有意的。
4. **不要为了清空报告改坏文字**。举例：`gap: 1px` 的分隔线被豁免是因为 1px 是结构不是间距；同一段里出现两次「最后」也可能有功能。

## 不要做的

- 别拿它当"AI 检测器"，也别把它的输出写进任何对外文案当卖点。
- 别指望它判断文章好坏——那要靠通读。
- `--fix` 只做数值取整，不做语义改写。文字层的修改永远由人做。

## 真实战绩

- 站点文案扫出「唯一要下载的是」「第一次同步」两处误报，据此把 `第一`、`彻底` 移出绝对化词表，并让重复出现的 emoji 降级为 info。
- 站点 42 处间距不在 4px 栅格，一条 `--fix` 归零，源码与构建产物复扫都是 0。
