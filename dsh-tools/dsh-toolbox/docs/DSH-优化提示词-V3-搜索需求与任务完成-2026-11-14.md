# DSH 优化提示词 V3：先匹配真实需求，再完成用户任务

本版遵循用户最新要求：本阶段只解决搜索需求、搜索意图和功能承接，不评估付费意愿。V2 的价格与付费验证流程暂不执行。以下整段可交给 DSH。

```text
请根据已完成的审计优化 DSH Toolbox。目标是让用户通过准确的搜索描述进入正确页面，并完成页面承诺的任务。不要把工具名称、页面数量、GitHub 星数、npm 下载量或问题帖数量当成关键词搜索量；不要继续设计价格、付费墙、会员、广告和收费实验。

项目：C:/Knowledge base/02-Project/dsh-toolbox
关联同步工具：C:/Knowledge base/02-Project/dsh-sync-hub
线上：https://www.dshtoolbox.com/
竞品参考：https://dsh-plugin.org/

先读当前 AGENTS、已有项目 SOP，以及：
- docs/关键词需求-搜索意图-功能匹配分析-2026-11-14.md
- docs/竞品复核与定价修正-2026-11-14.md
尊重未提交修改。报告是待复核的证据线索，不能假定线上和本地永远一致。当前报告已核对页面、源码与公开用户问题，但没有 GSC/Keyword Planner 月搜索量，也没有完成全部浏览器交互验收。

一、成功标准
1. 每个入口都写清用户要做什么、输入什么、获得什么、哪些情况不支持。
2. title、H1、首段、工具结果和 FAQ 指向同一任务，没有串页标题或过度承诺。
3. 修复已发现的操作断点，使用隔离合成数据验证；不在真实用户会话上进行删除、修复和同步试验。
4. 保留现有有用 URL；优先修改已有页面，不为近义词大量铺页。
5. 输出逐项证据和测试结果，区分已实现、文档声明、实际验证、未验证。
6. 未获得量化数据的关键词标记未知，不编造搜索量、流量预测、排名或收入。

二、先复现并修复已有问题

A. 页面事实和承诺
- what-is 中文 title 被写成“dsh 命令怎么用”；Claude Code 比较页中文 title 写成 Codex；Codex 比较页写成 OpenCode。检查最新内容映射并修正中英文对应。
- 首页把所有工具说成浏览器运行，实际上 Sync Hub 是自托管 Node CLI；Doctor 只读诊断，不自动修复索引。首段、卡片、FAQ、结构化数据和隐私说明保持一致。
- “想要一键版？”现为邮件需求登记，标注“登记一键清理需求（尚未上线）”；不能计入已交付功能。源码已有全选，不要再写只能逐个选。
- 核对官方桌面文档与 Releases，区分桌面安装包和 npm CLI。删除“所有使用方式都没有独立安装器”的泛化表达，按实际产品选择给出官方来源。预发布版不能当稳定版推荐。
- Android 分清官方/社区产品、手机本地运行/远程连接、APK/Termux。不能绝对说没有 Android App。不要下载或背书未验证安装包。
- 插件冲突分为“同版本已复现”“配置风险”“功能重叠”“未验证”，不得把共同依赖或两处按钮重叠统一写成不能共存。

B. 同步流程
- 复核网页 pair 未传 home/state，而 sync 传 home，导致默认状态目录与按 home 哈希的目录不一致。只在隔离环境中用合成路径/状态复现；选择最小修复，让教程前后使用一致的状态位置，不打印令牌。
- 修复 SyncHubPage 将 tree/main/... 再拼 blob/main/docs/... 的错误手册 URL，验证最终地址。
- 将“文件同步成功”和“目标机列表可见、可打开、可继续”分别验收。覆盖相同系统不同目录及可测试的跨系统路径。没有相应系统环境时明确未验证，不能模拟通过后声称完成真实双机验收。
- README 未实现的附件、PWA、Web 控制台、自动持续同步、一键恢复不得写成已有功能。

C. 清理器
- 不能接受任意目录却生成硬编码默认 .dsh/sessions 命令。浏览器可能无法获知真实绝对路径，需让用户明确填写或确认，不能从相对路径猜。
- 取消全部选择后清空/禁用旧命令。切换目录后不能保留上一次方案。
- 对平台路径、空格、引号、$、反引号、通配符、换行等按各 shell 的真实规则处理，不能用 JSON.stringify 冒充 shell 转义。Windows 使用 PowerShell LiteralPath 语义；约束目标在用户确认的目录内。先 dry-run/预览和备份，避免无必要的递归删除。
- 不凭文件大小或时间认定会话可删；说明运行中会话、索引和缓存一致性限制。若目前不能安全生成某种命令，就禁用该场景并解释，不输出危险占位命令。
- 用临时合成目录测试，不触碰真实 ~/.dsh、.ohdsh、DSH_HOME 数据。

三、按搜索者的任务完善页面

1. 安装/下载：官方来源 → 桌面或 CLI 选择 → 适用版本与系统 → 首次启动/模型配置 → 工作区与权限 → 完成一个简单任务 → 常见失败分流。第三方帖子里的解决办法必须验证，不能照抄成为确定答案。
2. 插件：按“我想完成什么”筛选。区分用户插件与内部库，给用途、安装/卸载、版本、实际测试状态、限制。现有免费方案能解决任务时直接提供准确指引。
3. 会话消失：区分文件已丢失、文件在但索引缺项、列表可见却打不开、升级后运行时错误、跨系统路径问题。Doctor 只承诺其检查范围；无索引差异不代表问题不存在。
4. 技能审计：分开名称/描述目录开销、潜在全文开销、运行时真实注入、累计计费与缓存。明确字符估算而非模型 tokenizer、读取数量限制。不以体积单独决定归档价值。
5. Context Budget：明确手填参数的来源和单位，“每轮输入”为新增上下文，不是重复发送的整个请求；展示固定增长假设、输出预留、误差。不承诺精确剩余轮数、实际账单或自动压缩。
6. Zstd：当前只做帧结构检查。标题和卡片不要暗示解压阅读聊天。明确不解压、不导出、不恢复；帧数不等于对话轮数。大文件能力需真实测量后表述。完整内容查看器暂列候选，不立即扩建。
7. De-AI：定位为文本模板痕迹和 UI 代码规则检查，入口直接对应输入区。不能包装成 AI 作者身份检测器或自动 humanizer。文本与 CSS 两个任务分清，不批量建近义页面。
8. Docker/比较：写清版本和验证状态。比较页不虚构成功率、速度或成本；未做同任务同模型实测时只给有来源的功能差异与适用条件。

四、调整首页表达，不扩大项目

可用主标题：Tools and guides for DeepSeek Harness / DeepSeek Harness 工具与使用指南。
优先入口：安装并完成第一次任务、检查会话列表问题、查大文件并准备清理、按任务找插件、跨电脑同步（自托管 CLI）。
保留技能估算、上下文估算、Zstd 帧检查作为专业工具；De-AI 放适当的次级位置。这是基于任务匹配的建议，不是假称这些入口搜索量排序已被验证。
产品名作为副标题保留，主要按钮用动作表达。修改 UI 时依用户规则优先使用现有 Open Design 和项目组件，不全面重做设计系统；已有 SOP 优先，不超量加载技能。

五、搜索验证与 SEO/GEO

- 形成一张 keyword-intent-map：候选词、语言、地区、意图、目标 URL、需求来源、搜索量来源/未知、目前能力、缺口、验收方式。
- 已有授权数据时读取 GSC 近 28/90 天 query/page/country/device 的展示、点击、CTR、位置。缺访问就标记待补，不阻断已可完成的纠错。
- 可用 Keyword Planner 历史数据时记录地区、网络、月份和近似变体，展示区间原值；不要将广告竞争当自然搜索难度。不要为此擅自购买工具、充值或开广告。
- 问题帖证明有人遇到问题，不能证明精确词有多少搜索。中文翻译词不是中文需求已经验证。
- 保持 canonical、双向 hreflang、sitemap、真实 404 与已有内链；检查变更后 title/H1/FAQ/Schema 同步。需要调整 URL 时才做准确重定向，避免无必要迁移。
- GEO 内容以简短准确答案、适用版本、输入输出示例、限制和一手来源为主。不虚构测试、评分、用户或引用，不把 llms.txt 或 Schema 当作 AI 推荐保证。
- 先利用现有统计和合成样例判断任务完成。不要为了漏斗擅自加入与“本地处理/无遥测”承诺冲突的跟踪；不采集聊天正文、路径、文件名、技能内容和密钥。

六、验证与交付

运行项目已有 build、必要检查和相关测试。核心模块已有 20 项测试通过不等于整站功能通过；对本次修复的配对状态、自定义清理目录、特殊字符和零选择旧命令增加必要行为验证。浏览器测试应使用合成文件，检查中英文、桌面/移动布局及从入口到结果的完整流程。

交付清单：改动文件与原因、关键词/意图/URL 对照表、真实功能边界、测试与浏览器验证结果、未能验证项目、后续所需账号数据。不要以“SEO 分数提高”代替用户任务完成。

遵守用户的代码同步规则：凡本轮实际编写或修改的代码，保留在原项目目录并同步到 FindSomeSkills/workspace 后 push，记录提交；未 push 不声称代码任务全部完成。不得修改 VPN/代理、DSH 开机启动或生产会话数据。
上线依据当前会话已有授权范围处理；有部署授权时验证后部署并复查线上，没有时先给出完整可审核的改动与验证结果。不得把未部署的代码描述成网站已生效。
```
