# DSH 优化提示词 V2：先核实免费替代，再验证收费

> 2026-11-14 最新任务调整：用户要求先验证搜索需求、搜索意图与功能承接，付费意愿留待以后。执行时改用 [V3 提示词](<C:/Knowledge base/02-Project/dsh-toolbox/docs/DSH-优化提示词-V3-搜索需求与任务完成-2026-11-14.md>)；本版付费验证步骤暂不执行。

此版本替代旧提示词的执行顺序与商业假设。将以下整段交给 DSH；本轮目标是可靠工具、明确差异和可验证的需求路径，不是自动上架未经证实的价格。

```text
请实际优化 DSH Toolbox，按“核对竞品 → 修复真实问题 → 证明一个剩余价值 → 验证付款”的顺序执行。不要沿用之前默认 $49–99 服务或 $9–19/月订阅的方案，也不要擅自换成 $9.9 等另一个无依据价格。

项目：C:/Knowledge base/02-Project/dsh-toolbox
本站：https://www.dshtoolbox.com/
竞品：https://dsh-plugin.org/

先读：
1. docs/竞品复核与定价修正-2026-11-14.md
2. docs/CODEX-SEO-GEO-美元变现评估-2026-11-14.md（技术发现仍需复现；商业假设已被本次修正）
3. 当前AGENTS和项目已有SOP；尊重未提交修改，不覆盖其他人的工作。

一、先明确不能假设什么
- 竞品免费提供目录、安装管理和故障教程，相关开源插件还有上下文审计与同步能力。免费替代不是只有官方文档，还包括插件和用户已有的AI助手。
- 目录数量、页面数量、Schema数量、GitHub星数、工具使用量都不是付费意愿。
- 竞品页面的“全部验证”“几万个插件”等是其自述，未独立核验不可背书；也不能因为计数不一致就指控造假。
- 不默认本站不可替代，不默认有人愿买人工服务，也不因竞品免费就认定所有服务都无价值。
- 本阶段保留免费工具；不直接建会员、支付墙、广告系统、云聊天存储或大量新SEO页。

二、做一张有证据的替代方案表
逐项比较：插件发现/安装管理、安装排障、技能与上下文审计、会话同步、索引诊断、清理与备份。
每行记录：用户要完成的任务、竞品/官方/开源免费方案、来源链接、版本、需不需要安装、数据处理位置、本站现有能力、实际差异、测试状态。
至少核查：
- https://github.com/dshplugin/dsh-plugin-hub
- https://dsh-plugin.org/tutorials/troubleshooting
- https://github.com/zhenyu98/dsh-context-doctor
- https://github.com/rosa42/dsh-sync （沿公开链接核对版本与原作者，不凭名字猜用途）。
官网文案、README说明、源码检查与实际运行分别标记，不混写成“已经验证”。不要在用户生产DSH环境随意安装竞品；必要测试用隔离环境和合成数据，不修改VPN/代理和DSH开机启动。

如果免费方案已经完成任务，优先提供准确指引，不重新造同样的功能。不得把“暂未查到竞品某功能”写成“竞品一定没有”。

同步比较不能只看“都能同步”：dsh-sync README默认workspaceState:false，并警告共享workspace.json覆盖风险；本站Sync Hub声称处理索引同步。用双机合成样例验证文件、列表、标题和冲突处理，不把两者当完全等价，也不凭差异宣称收费成立。

三、先完成已证实问题的最小修复
重新检查后修复尚存在的问题：
- 两篇中文对比页title对象串错；title/H1/描述/OG/Schema对齐。
- “26对插件不可共存”过度承诺：按已复现不兼容、配置风险、功能重叠、未验证分类，列版本和证据。
- 六个浏览器工具与自托管Sync Hub的数据边界；Doctor只读诊断不能说自动修复。
- SkillAudit、IndexDoctor将本地输入拼入innerHTML的问题；安全渲染并加入不可信字符串回归。
- 文章发布/修改日期倒置、来源URL不可点击、内链锚文本与能力错配。
- Zstd一次读取大文件与“大文件也轻量”的无依据保证；实测或诚实标注限制。
不重写整个项目，不把已有sitemap、hreflang、llms.txt、FAQ重新添加当成果。旧220 URL仅作审计快照，本轮重新计数。

四、只选择一个值得验证的剩余问题
可以研究“DSH不能启动时仍能在浏览器检查文件副本”“迁移后磁盘文件与索引不一致”等场景，但不得先宣称独特。
使用同一份合成样例，对本站和免费替代比较：能否识别问题、步骤/耗时、误判、适用版本、数据边界。节省时间和费用必须实测，不写空泛百分比。
最多推荐一个方向，写清谁遇到问题、免费方案为何仍不够、本站新增什么可验收结果。
若没有明确差异，直接建议维持免费参考工具并暂停商业功能，不硬凑商业化。

五、建立最小需求入口，不预设销售成立
在最相关的工具结果或故障页增加不打扰使用的入口，例如“现有方法仍未解决？描述你的问题”。提供真实反馈渠道；没有有效收件人/服务端时完成预览并列出缺项，不放假按钮。
只询问系统/DSH版本、问题、已尝试方案、期望结果和可选回复方式；不要收密钥、完整会话、完整路径或默认上传日志。先说明用途，严格保持免费本地工具的隐私边界。
补必要的维护者、非官方身份、联系和隐私说明；没有已开售产品，不为凑商业化批量建pricing/checkout页面。
保留现有no telemetry承诺。先用允许的GSC/汇总数据和手工反馈记录；新增前端统计需先明确数据字段及披露，不采集输入内容。隐私优势必须以实际行为为准。

六、按真实需求决定报价
先准备10次目标用户访谈提纲与记录表，重点问过去的具体问题、尝试过的免费工具、未解决的影响、此前是否买过帮助。不要虚构访谈或擅自联系别人。
对有明确需求且我们能交付的人，准备一个范围清楚、可验收、有限售后的个别报价方案；价格依据交付成本、真实替代成本与客户反馈，不照抄以前的数字。
证据依次区分：看过页面、使用工具、反馈问题、请求协助、接受具体报价、真实付款、完成交付、退款/复购。免费用户数量不能充当付费人数，口头支持不能充当订单。
真实独立客户付款才验证成交，测试单/熟人支持单单独标记；记录支付成本、退款、交付与售后工时。没有收款主体/账户就列出必要条件，不擅自注册或虚构主体。
至少出现3个真实完成交付的付费案例且需求可重复后，再建议标准化套餐；订阅须另有持续使用与续费证据，不因首单就建SaaS。
14–30天是观察窗口，不是收益保证。若接触不到目标用户，应诊断分发；若用户免费即可解决，应停止该付费方向；若有付款但工时亏损，缩范围或停止。不能仅通过继续降价或扩页掩盖问题。

七、SEO/GEO只围绕实际价值优化
保留有用页面和既有URL，优先深改少数有实测依据的故障页，写明版本、输入、预期输出、限制、来源和复测日期。
免费替代该推荐就推荐，比较文案客观；不复制竞品文章，不堆“最全/最好”，不在未实测时创建贬低竞品的比较页。
百度、更多语言、海量插件页面、FAQ/llms.txt扩写不作为本轮重点。没有GSC/搜索数据就不虚构关键词搜索量或预期流量。
准备合规社区答复和演示草稿，但不自动发帖、私信、购买广告或外链。

八、验收与交付
运行现有build、核心测试、schema、内链与sitemap检查；补与具体修复对应的回归，避免全局自动重写。
用合成数据检查三个核心工具demo、空输入、坏输入、大小边界和360/390/768/1440布局。无法测试的明确写未测，不用静态HTML冒充浏览器验收。性能分实验室与真实用户数据。
按用户规则使用Open Design/AnySearch；仅最少必要skills。代码按GitHub同步SOP同步FindSomeSkills/workspace并push，依既有发布授权处理部署，验收线上状态。文档留知识库，凭据不入库。

最终给我：
1. 有来源和测试状态的竞品替代表。
2. 已修复事项、文件、测试、commit/部署状态。
3. 最多一个有证据的差异方向，或明确“不值得继续商业化”。
4. 真实可用的需求入口和下一步访谈/试单材料。
5. 当前收费证据处于哪一级；如果还不知道价格，就直接说不知道。

本轮成功标准是降低错误与试错成本，得到真实需求和成交证据；不是宣布必然月入多少美元。
```
