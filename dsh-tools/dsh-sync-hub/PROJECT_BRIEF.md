# DSH Sync Hub — 项目简报（新会话开场文件）

> 本文件是「DSH 跨设备同步工具」专有会话的开场上下文。新会话第一件事：读完本文件，再开始工作。

## 一、目标

做一个可部署到网站上的工具，解决 **DSH（DeepSeek Harness）工作区与会话在多设备间自动同步** 的问题：

- 多台电脑之间：会话记录、工作区绑定、续接上下文
- 手机端：能继续电脑上没做完的工作
- 现状：DSH 没有官方同步；社区插件（dsh-session-sync / dsh-remote-mobile）各自解决一半问题

## 二、已完成的调研（详见知识库）

- `09-Agent/DSH多设备同步方案调研-2026-11-13.md`（本机知识库）
- 结论摘要：
  - 会话存储：`~/.dsh/sessions/<workspace-hash>/<session-id>/session.v4.jsonl.zstd`（多帧 zstd，追加写）
  - 索引：`~/.dsh/storages/workspace.json`（工作区与会话 ID 列表）
  - 插件方案：`dsh-session-sync`（git 镜像 + append-only 三方合并，冲突保双份）；`dsh-remote-mobile`（单实例远程接入，手机扫码）
  - 缺口：没有一个「网站化、多用户、可视化」的同步与恢复产品

## 三、需求草案（待在新会话中细化成 PRD）

### P0（MVP）
1. 设备注册与配对（二维码/一次性码）
2. 会话增量同步：按会话目录做增量（文件级）上传/下载
3. 冲突处理：同一会话两边都改 → 保留双份（fork 文件），绝不静默覆盖
4. 工作区映射：不同设备上的工作区路径不同，需要路径别名映射
5. Web 控制台：设备列表、同步状态、历史版本、一键恢复
6. 安全：凭据不入库、传输 TLS、服务端加密存储

### P1
7. 手机端适配（PWA）
8. 版本回滚到任意时间点
9. 多用户/团队共享（可选）
10. 与 Obsidian 知识库的联动（vault 同步独立）

## 四、技术方向（待定，需在会话中做选型对比）

- A：自建同步服务（Node/TypeScript + SQLite + REST/WebSocket + S3 兼容存储），客户端为 DSH 插件 + CLI
- B：基于 git 的镜像服务（复用 dsh-session-sync 的思路，做成 SaaS）
- C：组合现有插件 + 轻量控制台（最快落地）

## 五、硬性约束

- 会话文件按**不透明字节**处理，不解析 zstd/JSONL（避免版本耦合）
- 必须同步 `sessions` + `storages` 索引，否则会话不显示
- 两端 DSH 版本需一致（0.2.x 用 v4 格式）
- 凭据（`.credentials.yaml`）绝不进入同步仓库
- **代码必须 push 到 `FindSomeSkills/workspace`**（知识库规则第 11 条），源码留在本目录，不复制进知识库
- 开发类任务若走知识库会话，需按规则先路由
