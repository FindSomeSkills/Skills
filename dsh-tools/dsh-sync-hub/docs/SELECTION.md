## 三、为什么不选 B（决定性理由）

1. **二进制增量失效**：git 的 delta 压缩对大二进制收益极低，22 MB 会话每改一次近似再存 22 MB。实测会话最大 22.8 MB，若一天改 10 次就是 200 MB+。
2. **索引冲突 = 用户丢会话**：`workspace.json` 是单个 JSON，git 冲突需要人工解；而它正是「会话在列表里显不显示」的开关。PRD 的 G5 直接落空。
3. **与目标形态不符**：产品目标是「可部署到网站上的工具」，B 本质是把网站换成 GitHub 网页。
4. **无法做设备级吊销/审计**：PRD §10 的 T2/T3 威胁无法缓解。

B 唯一优势是运维成本，但代价是把核心正确性交出去。

## 四、为什么不单用 C（但保留它做入口）

1. **覆盖面天然残缺**：插件只能作用于「装了插件的那个 DSH」。本机实测：桌面版已卸载、网页版在线，手机完全没有 DSH —— C 对三者中的两个无解。
2. **没有服务端状态**：无版本历史、无跨设备冲突决策面板、无「手机上看一眼」。
3. **上游兼容性风险集中**：两个插件都标注兼容到 0.2.2-rc.1，而本机是 0.2.1-rc.2；版本再往前走一步就都不保证。

**C 的可复用部分**（只取这些）：

| 复用项 | 来源 | 怎么用 |
| --- | --- | --- |
| append-only 三方合并思路 | `dsh-session-sync` | 借鉴为 §8.4 的前缀校验增量，但不依赖它 |
| 冲突保双份、绝不 force 的价值观 | 同上 | 落成 PRD §9.2 |
| 配对码 + 二维码 UX | `dsh-remote-mobile` | 落成 §6.1 配对流程 |
| 插件作为 UI 入口 | 两者 | 以后做「在 DSH 里点一下同步」的薄插件，调 Agent 的 CLI/本地端口 |

## 五、最终形态：A 的骨架 + C 的入口

```
┌──────────────────────────────────────────────────────────┐
│  Hub（自建，部署到网站）                                   │
│  Node + node:http + 内容寻址块存储 + 元数据                   │
│  REST + SSE  ·  设备鉴权  ·  版本表  ·  冲突队列              │
└───────────────▲───────────────────────┬──────────────────┘
                │ HTTPS                 │ 控制台（PWA，C 的入口形态）
   ┌────────────┴───────────┐      ┌────┴─────────────────┐
   │ Agent（运行面无关）      │      │ Web 控制台            │
   │ Node CLI / 守护进程      │      │ 设备·工作区·会话·冲突  │
   │ --home <DSH Home>      │      │ 手机 = 只读 + 下指令    │
   └────────────▲───────────┘      └──────────────────────┘
                │ 读/写磁盘（不解析负载）
   ┌────────────┴───────────────────────────────┐
   │ DSH Home：~/.dsh（web/v4）、~/.ohdsh（desktop/legacy）…│
   └────────────────────────────────────────────┘
```

三条边界（写死，防走偏）：

1. **Agent 只认 home 路径**，不认宿主；插件永远只是可选入口。
2. **Hub 不解释负载**，只做字节搬运 + 索引语义合并。
3. **手机不承载会话**（PRD §3.3 T3）。

## 六、技术栈（v1）

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | Node ≥ 20（本机 24.19.0） | Agent 与 Hub 同一语言，减少交付面 |
| HTTP | `node:http`，零框架 | MVP 不引依赖，避免安装/审查成本 |
| 存储 | 文件系统：`meta/*.json` + `blobs/<hh>/<sha256>` | 先跑通正确性；接口留好，后换 SQLite/S3 |
| 哈希/加密 | `node:crypto`（sha256、scrypt、aes-256-gcm） | 无原生编译依赖 |
| 前端 | 单页 + 原生 DOM（后续 PWA） | 控制台是工具不是门面；UI 稿走 Open Design |
| 测试 | `node:test` | 内置 |
| 打包 | 不打包，`node src/...` 直跑 | MVP 阶段可读性优先 |

**明确不做**：不引 Express/Fastify/TypeORM/better-sqlite3（都要装依赖或原生编译），MVP 阶段任何第三方依赖都是负债。

## 七、决策记录（ADR 摘要）

| ADR | 决策 | 为什么 | 何时重新评估 |
| --- | --- | --- | --- |
| ADR-001 | 引擎做成运行面无关 Agent，不做纯插件 | 插件覆盖不了已卸载的桌面版、手机、未来运行面 | 若官方出同步 API |
| ADR-002 | 冲突副本只存 Hub，不在本地造 fork 会话 | 改目录名/后缀的会话能否被 DSH 加载未验证（PRD R1） | R1 验证通过后可开「本地自动 fork」 |
| ADR-003 | 索引必须语义合并，禁止整文件 LWW | 两端各加会话时 LWW 会丢会话（= 会话消失） | 不重新评估 |
| ADR-004 | 先文件存储，抽象接口，后换库 | 先证正确性，避免过早引入迁移成本 | M2 完成后 |
| ADR-005 | 不引第三方运行时依赖 | 部署在用户自己的网站，依赖越少越安全 | 需要 SSE 压缩/限流等成熟中间件时 |
